# Candidate-figure discovery suite

The discovery suite extends the four main figures with the 34 designs specified
in the current brief. It preserves the complete selected evaluation population
and generates the same registered designs in each compatible configuration.
It does not choose a paper figure or rank candidates by favorable outcomes.

The formula mapping is in [candidate_formula_mapping.md](candidate_formula_mapping.md).
The registry is generated by `candidate_registry.py` and copied into each bundle.
Its cards distinguish learned behavior, model centers, candidate references,
proof-derived directional conditions, reference-only illustrations, and algebraic
QA. The original Proposition-5 norm condition remains an audit measurement.

## Commands

```bash
# Extend protected cached measurements and render the candidate suite.
./run_all.sh --recompute-experiments --figure-suite candidates

# Re-render saved candidate scalar products; no trajectory or model reads.
./run_all.sh --plot --figure-suite candidates

# Reload the suite saved for each exact model/sampler/g/T/N/center configuration.
./run_all.sh --plot

# Explicitly select the existing four main designs.
./run_all.sh --plot --figure-suite main
```

The existing model/scheduler filters and `--device` behavior apply. `auto` uses
all visible CUDA devices, with one record shard per device and one coordinator
progress bar at a time. Each stage follows generation's convention of one local
worker plus spawned workers for the other devices. This audit host has no visible
CUDA device; CPU fixture and real-device evidence are recorded separately.

`theory_suite.json` is a theory-owned manifest beside a scientific run's analysis
directories. It records the selected suite and exact configuration without
modifying protected generation or SSCD manifests. Copied candidate bundles can
be rendered with `./theory_validation.sh --bundle PATH --plot`.

## Reuse and stage publication

The existing schema-3 main analysis supplies audited source identities, fixed
candidate atoms/weights, the independent reference center, base scalar shards,
and cached initial seed inputs. The new endpoint stage opens each required
protected record once through the shared cache reader, promotes canonical epsilon
before arithmetic, and computes all new tensor-dependent statistics together.
It never runs a learned model or synthesizes counterfactual network predictions.

Endpoint measurements and dose/control arrays are saved before path integration.
Compact segment payloads contain candidate-relative affine logits, slopes,
current weights and scalar geometry; they contain no clean-estimate trajectory.
A separately hashed integration stage consumes these payloads and the unchanged
candidate bank. Changes to integration or summary recipes reuse valid endpoint
shards. Invalid or interrupted derived shards are repaired individually.

The integration stage preserves independently calculated endpoint gains, all
four norm/directional bounds, their uncertainties and adjacent gaps, and the exact
directional average as an identity diagnostic. Its estimates are not formal
floating-point certificates. Unresolved integration does not erase endpoint
measurements. Conditional gain, endpoint profiles, and source/arithmetic precision
statuses remain separate fields.

A completed publication requires all requested computational stages. Partial
endpoint results remain inspectable in their staged gallery; a failed stage does
not replace an existing complete suite index. Forced summary rebuilding stages a
replacement and preserves the prior publication until completion. The original
main-analysis bundles and their figures are read-only inputs.

```text
outputs/<scientific_run>/theory_candidates/<analysis_hash>/
  registry.json
  analysis_manifest.json

  reference_initial.parquet, reference_snr.parquet, bank_geometry.parquet

  summaries/

  comparison_summary.csv
  index.html
  IR/, UB/, IA/, MD/, PF/, TS/, TR/
  qa/, last_prediction_geometry/
```

`reference_initial.parquet` contains one row per distinct **evaluation** seed.
The independently estimated model center still uses the disjoint reference seed
block; its complete provenance is retained in `center_metadata.json`.

Each figure has PNG/PDF exports and a JSON sidecar. Fixed snapshots, outcome
cohorts, and all five recovery thresholds get explicit variants. All registered
designs occur in the gallery and comparison table, including unavailable designs.
The top-level `outputs/theory_candidates/index.html` links configurations and
compares the same estimands without pooling their different candidate laws.
All pages are local HTML with no CDN or network dependency.

Each card gives its question, axes/formulas, result/equation mapping, evidence
type, populations and weights, counts, numerical/applicability status, source
links, and a descriptive result. The cards state what the measured pattern would
and would not establish. No significance or automatic best-figure selector is
used. The target-group hash split is exploratory stability analysis, not a new
untouched confirmatory sample.

## Fixed numerical recipes

- Fixed outcomes are same-seed terminal SSCD >0.75 and <=0.75; all samples remain.
  Continuous bins are [0,.1,...,1], with explicit out-of-range status counts.
- Within each subset/group, each represented prompt has equal total weight,
  divided over its included seeds. Initial unconditional views use unique seeds.
- Dose fractions are `linspace(0,1,21)` plus in-range `1/g`; source-trajectory
  SSCD is a descriptor, not a newly evaluated outcome for each dose.
- Non-target controls are selected by a fixed salted bank/target/atom hash and
  retained across all seeds and updates. No measured gain enters their selection.
- Direction-normalized quantities use the float64 subtraction screen for the
  observed branch gap and matched displacement. Source-direction sensitivity is
  a separate diagnostic; its full budget remains in integrated-margin uncertainty.
  Zero/unresolved directions, gain underflow, and endpoint sign remain distinct.
- Recovery thresholds 0.1, 0.2, 0.3, 0.5 and 1.0 are diagnostic latent RMSE
  thresholds. Never-reached trajectories retain censoring statuses.
- Terminal theorem designs require the saved structural clean-update gate.
  Incompatible samplers may show TR01 only under `last_prediction_geometry`.

## Validation and audit scope

Small CPU tests cover the 18 acceptance categories from the brief, including
independent scheduler replay, signed endpoint gains and concavity, the ordered
bounds and independent Eq. 69 integration, paired synchronization, censoring,
fixed controls/windows, exact configuration routing, interruption recovery, and
real spawned-worker execution. Synthetic sign tests concern constructed
mathematical examples; none requires a trained model to show a favorable result.

The full-population audit uses the existing dispatcher on this CPU-only host.
`outputs/theory_candidates_audit/run_cpu_workers.py` is a reproducible audit
harness that supplies repeated CPU devices to exercise that dispatcher; it does
not change the public CLI's device policy. Each execution report records actual
worker PIDs, devices, assigned records, and thread budgets. CUDA parity tests are
skipped on this host and reported separately when CUDA hardware is available.

Summary aggregation reuses finite-mask weights and per-subset invariants. Exact
parity checks covered 25 saved real-data tables, 24 synthetic tables with mixed
missing values, and 30 independent helper cases. On the same 1,000-row saved
smoke, single-thread summary time fell from 246 to 67 seconds (about 3.7 times
faster); this timing was measured under concurrent host load. Completed full-run
endpoint and integration shards were hash-verified and reused for the summary
refresh. A runtime guard blocked trajectory and prediction reads during that
refresh while preserving existing small target/schedule provenance checks.

`outputs/theory_candidates_audit/` contains streaming scalar checks, population
counts, independent endpoint/integral residuals, original and refined margin
statuses, saved-plot guards, and final publication checks. The plot guard rejects
tensor/array/model-state loads, analytical reducer imports, and network access.
The simple saved-suite command is exercised with that guard after publication.

Every protected file in the small fixtures is checked by content hash and
modification time. For the real matrix, the audit captures a complete protected
metadata inventory and content hashes for all scalar metadata, schedules, and a
declared representative tensor subset; this is not an exhaustive content hash
of all large trajectory files. Raw payload hashes are also checked by the
existing cache reader when each required record is loaded. All existing main
bundle files are separately compared by full content hash and modification time.

All four complete bundles retain all selected prompt runs and evaluation seeds.
Every configuration has all 34 registered designs and 69 fixed variants; available
variants have both PNG and PDF exports. Counts below describe saved observations,
not independent statistical replicates or pooled cross-model estimates.

| SDv2 / DDIM | 86 | 1,720 | 84,280 | 30,848 | 53,432 | 65 |

These are stable signs of the candidate-reference matched gain evaluated from
the observed cached branches; magnitude-underflow cases keep their resolved
log-odds sign. They are separate from confidence in unobserved exact network
predictions. Source sensitivity and uncertainty-aware margin statuses remain
available alongside the observations.

The original norm margin has no resolved positive cases in any configuration.
The separately named projected-variation refinement has 5,487, 426, 266, and
3,428 resolved positive cases, respectively; it is not substituted for the
original condition. Many margin signs remain unresolved under the retained
source-sensitivity budgets even though their endpoint observations and
quadrature estimates are available. Raw directional-average sign differences
in saturated regimes are retained and checked against their uncertainty statuses.

Each completed configuration passed 114 saved-scalar contract checks. Across
820,260 eligible transitions there were no producer endpoint/integral, bound-order,
directional-identity, or quadrature-budget flags. The largest independently
measured Equation-69 discrepancy was 4.389e-8; the largest discrepancy divided by
its own recorded numerical allowance was 0.02270. These checks concern numerical
estimates, not rigorous floating-point or pretrained-model certificates.

All four saved final updates fail the structural clean-update gate, so TR01–TR04
are explicitly not applicable. Their last-prediction geometry remains in its
separate namespace. SDv1/DDPM also marks independent scheduler-replay QA (MD01)
unavailable because the required independent stochastic replay inputs are absent.
The other learned-trajectory and local matched-update measurements remain usable.
